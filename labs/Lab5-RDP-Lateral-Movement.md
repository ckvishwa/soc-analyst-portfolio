## Objective

Simulate RDP authentication using credentials stored in Windows Credential Manager and detect the resulting Windows Security events in Splunk. This lab demonstrates explicit credential use and RDP-related authentication telemetry on a single host. It does **not** demonstrate lateral movement because the connection target is `127.0.0.1`.

---

## NIST SP 800-61 Incident Response Phase

> **Phase 2: Detection & Analysis**  
> Explicit credential use was observed through Event ID 4648 and correlated with local authentication activity. Malicious lateral movement was not confirmed.

## Analyst Narrative

During authentication-log review, two Event ID 4624 records with Logon Type 2 from `127.0.0.1` were followed by Event ID 4648 at the same timestamp.

### Confidence statement

**Observed:** Event ID 4648 recorded explicit credential use. Event ID 4624 recorded successful local interactive logons.

**Assessed:** The sequence is consistent with a user or process supplying alternate credentials while initiating an RDP-related authentication workflow.

**Not confirmed:** The activity does not prove lateral movement, Pass-the-Hash, or credential theft. The source and destination were the same host, and no NTLM hash was used.

Event ID 4648 is a useful investigation signal, but it is not inherently malicious. It can also be generated by `runas`, scheduled tasks, administrative tools, service accounts, and legitimate remote-management activity.

---

## Attack Simulation

```cmd
:: Enumerate stored credential targets and usernames
cmdkey /list

:: Enable RDP in the lab
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 0 /f

:: Connect to the same host
mstsc /v:127.0.0.1
```

`cmdkey /list` reveals stored credential targets and usernames. It does not display the stored password in plaintext. Credentials protected by Windows Credential Manager may still be usable within the logged-in user's context without exposing the password directly.

## Detection Query

```splunk
index=main (EventCode=4624 OR EventCode=4625 OR EventCode=4648)
| rex field=_raw "Logon Type:\s+(?<LogonType>\d+)"
| rex field=_raw "Account Name:\s+(?<TargetUser>\S+)"
| rex field=_raw "Source Network Address:\s+(?<SrcIP>\S+)"
| rex field=_raw "Process Name:\s+(?<ProcessName>[^\r\n]+)"
| rex field=_raw "Target Server Name:\s+(?<TargetServer>\S+)"
| table _time, host, EventCode, TargetUser, SrcIP, LogonType, ProcessName, TargetServer, ComputerName
| sort _time
```

### Explicit credential-use query

```splunk
index=main EventCode=4648
| rex field=_raw "Account Name:\s+(?<TargetUser>\S+)"
| rex field=_raw "Process Name:\s+(?<ProcessName>[^\r\n]+)"
| rex field=_raw "Target Server Name:\s+(?<TargetServer>\S+)"
| table _time, host, TargetUser, ProcessName, TargetServer, ComputerName
| sort _time
```

### RDP-specific successful logons

```splunk
index=main EventCode=4624
| rex field=_raw "Logon Type:\s+(?<LogonType>\d+)"
| rex field=_raw "Account Name:\s+(?<TargetUser>\S+)"
| rex field=_raw "Source Network Address:\s+(?<SrcIP>\S+)"
| where LogonType=10
| table _time, host, TargetUser, SrcIP, ComputerName
| sort _time
```

## Alert Logic

```text
IF Event ID 4648 occurs
THEN identify the initiating process, account, target server, source host, and nearby 4624/4625 events

IF Event ID 4648 is followed by Event ID 4624 Logon Type 10 to another host
AND the account, source, process, or target is unusual
THEN raise a high-priority RDP credential-use alert

DO NOT label Event ID 4648 alone as malicious
```

---

## False Positives and Tuning

| Legitimate scenario | Validation approach |
|---------------------|---------------------|
| Administrator using `runas` | Confirm approved admin account, process, host, and ticket |
| Scheduled task using alternate credentials | Match approved task name and service account |
| Service account authentication | Baseline expected host and target relationships |
| Remote-management tooling | Validate signed process, management server, and change window |
| User connecting with saved RDP credentials | Confirm target, user intent, and normal behavior |

Avoid globally allowlisting all Event ID 4648 activity from an administrator or service account. Tune using narrow combinations of process, source, destination, account, and host role.

---

## Recommended Response Actions

1. Identify the process that generated Event ID 4648.
2. Confirm whether the account and target server are expected.
3. Review nearby 4624, 4625, 4672, and RDP operational events.
4. Check whether authentication reached a different endpoint.
5. Review stored credential targets with `cmdkey /list` without assuming plaintext-password exposure.
6. Reset credentials only when compromise is supported by evidence.
7. Escalate when explicit credential use is paired with anomalous destination, process, account, or post-authentication activity.

## Lessons Learned

1. Event ID 4648 records explicit credential use; it is not automatically malicious.
2. `cmdkey /list` reveals stored targets and usernames, not plaintext passwords.
3. Localhost RDP demonstrates authentication telemetry, not lateral movement.
4. Pass-the-Hash requires hash-based authentication evidence and should not be inferred from stored credentials.
5. Authentication events become meaningful when correlated by account, process, source, destination, logon type, and time.
6. Analyst conclusions should clearly distinguish **observed**, **assessed**, and **confirmed** facts.
