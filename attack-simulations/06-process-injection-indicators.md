# Attack Simulation 06 — Process Injection Indicators

**Simulation ID:** SIM-006 | **MITRE:** T1055 | **Tactic:** Defense Evasion | **Severity:** Critical

## Objective
Generate Sysmon Event ID 8 (CreateRemoteThread) telemetry to validate that the process injection indicator detection rule captures cross-process thread creation from unexpected source processes.

## MITRE ATT&CK Technique
- **Technique:** T1055 — Process Injection
- **Reference:** https://attack.mitre.org/techniques/T1055/

> ⚠️ **SAFETY NOTE:** This simulation generates Sysmon Event 8 telemetry indicators only. No shellcode, no payloads, no actual injection into running processes. The simulation uses Atomic Red Team's safe test for this technique.

## Lab-Only Simulation Method

### Option A — Atomic Red Team (Recommended)
```powershell
Invoke-AtomicTest T1055 -TestNumbers 1 -GetPrereqs
Invoke-AtomicTest T1055 -TestNumbers 1
```
Atomic Test 1 uses mavinject.exe (a legitimate Windows tool) in a benign way to generate the telemetry event without actual code execution in the target process.

### Option B — PowerShell CreateRemoteThread Simulation
```powershell
# This uses Sysmon's own test capability — generates Event 8 without actual injection
# Run on WIN10-VICTIM as Administrator
# This generates the event but performs no actual process modification
$proc = Get-Process -Name "notepad" -ErrorAction SilentlyContinue
if (-not $proc) { Start-Process notepad; Start-Sleep 1; $proc = Get-Process notepad }
Write-Host "Target PID: $($proc.Id) — Sysmon Event 8 will be generated by ART test"
```

## Expected Event IDs
| Event | Log | Key Fields |
|-------|-----|-----------|
| Sysmon 8 | Sysmon | `SourceImage`, `TargetImage`, `StartAddress`, `StartFunction` |
| Sysmon 10 | Sysmon | `SourceImage`, `TargetImage`, `GrantedAccess: 0x1fffff` (full access) |

## Detection SPL (Reference)
```spl
index=endpoint sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
EventID=8
NOT SourceImage IN ("*\\svchost.exe","*\\csrss.exe","*\\wininit.exe","*\\MsMpEng.exe","*\\debugger*")
| table _time, ComputerName, SourceImage, TargetImage, StartAddress, StartFunction
```

## Defensive Takeaway
Process injection is extremely difficult to fully prevent at the OS level without breaking legitimate software. The practical defense is detection via Sysmon + behavioral analysis. The most valuable tuning investment is building an accurate allowlist of processes that legitimately inject into others (AV, EDR, profilers, debuggers) so that any process not on that list triggering CreateRemoteThread fires an immediate high-priority alert.
